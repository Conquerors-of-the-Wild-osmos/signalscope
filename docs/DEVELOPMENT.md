## Окружение и команды

Для Gradle и используемой версии Loom нужен **JDK 25 или новее**.
Код компилируется для Java 21. Зависимости и версии заданы в
[build.gradle.kts](../build.gradle.kts) и [gradle.properties](../gradle.properties).

Команды из корня проекта для macOS/Linux:

```sh
bash ./gradlew build
bash ./gradlew test
bash ./gradlew runClient
bash ./gradlew runServer --args='--nogui'
```

На Windows используйте `gradlew.bat` с теми же задачами.
При первом запуске Gradle загружает зависимости и ресурсы Minecraft.
Режим `--offline` подходит, когда они уже есть в локальном кэше.

Готовый мод находится в `build/libs/`. Для обычной установки нужен основной JAR,
без суффиксов `-sources`, `-dev` или `-javadoc`.
Среда разработки автоматически подключает Fabric API, YACL, Mod Menu, SVC
и stub его API; отдельно копировать их в тестовый профиль не нужно.

## Проверки

`test` запускает JUnit 5. Существующие тесты находятся в `src/test/java/`:
маршрутизация голоса, геометрия приёма и блокировки, сетевые сообщения,
интерполяция, пассивный звук и сохранение состояния блоков.

После изменений взаимодействия или звука дополнительно проверьте игру:

1. Два игрока в одном измерении: рация у передающего, сигналоскоп у слушателя.
   Проверьте удержание, переключение по нажатию, прекращение при смене предмета.
2. Наведение сигналоскопа усиливает голос, отворачивание ослабляет его;
   без сигналоскопа в руке голос не слышен. Пассивный сигнал заменяется голосом.
3. Нажатие ПКМ на сундук открывает сундук; уже начатая передача при наведении
   на интерактивный объект продолжается.
4. Переход между измерениями, смерть и отключение удаляют недоступные источники.
5. Установите общую громкость Minecraft и громкость категории «Игроки» в ноль,
   затем восстановите. Проверьте восстановление пассивного звука, включая F3+T
   и убирание/возврат сигналоскопа в руку.
6. Проверьте передатчик с питанием и без него, переименование, повторный вход
   в мир и выгрузку/загрузку чанка.
7. Проверьте направление приёмника и его выход редстоуна. Включите блокировщик
   между источником и приёмником, затем проверьте связь двух источников внутри
   одной области блокировки.
8. Проверьте состояния текстур передатчика и блокировщика, HUD при разных
   GUI Scale, а также предметы в обеих руках от первого и третьего лица.

Автоматические проверки не заменяют прослушивание с реальными микрофонами.

## CI

[Workflow](../.github/workflows/build.yml) собирает проект и загружает JAR
как артефакт. Для внутренних pull request он публикует ссылку на сборку.
Проверка Docker Compose запускает сервер с собранным JAR.

Push в `main` также запускает настроенный deployment и создание/обновление
GitHub Release. Релиз содержит основной JAR и его копию
`signalscope-fabric.jar` со стабильным именем для Docker Compose.
